# HyperFurion VK 3

Proposal, revised. Written against 2.4.0. A design, not a schedule.
The current release is declared in `pyproject.toml`. The rungs in
`ROADMAP.md` stay the longer direction.

## The bar

No. An opt-in underline is not a version 3, and the two engine
accessors that would start it are not one either.

This project uses semantic versioning. Look at what actually earned a
number. 1.2 put unfinished speech in the document and repaired it there.
That is molten dictation, and it is still what 2.4 does. 2.0 added Kai
and the consent machinery around it: drafted commands, held rewrites, a
dictionary you accept, a probe, an intent channel. 2.2 made Windows a
first-class desktop. 2.4 grew the spoken grammar into an editor and
stayed a minor. A major here is a new era, and a break with the era
before it. A flag that defaults to off is a feature. A unit test is a
commit.

Version 3 is the break with 1.2. The document stops being the
scratchpad. Three things ship together, on by default. If one of them
is missing, the release is not 3.0.

## The three things

### 1. The app receives finished words only

On Linux, Windows, and macOS, the focused app is given text when it
freezes, typed once, forward. The injection worker no longer backspaces
a preview it already placed in the field.

`desired_text()` stays the string the worker uses today, frozen plus
molten, and it is the wrong string to type under this rule. The engine
exposes `committed_text()` and `molten_text()`. The sink types the
frozen delta. The molten tail never enters the app.

This is the behavior change, and it is the default. It is why the major
number is honest. A click in the middle of a sentence can no longer
land a repair in the wrong place, because the repair happens before the
text is real. "Scratch that" on the unfinished tail clears words that
were never committed, emoji included. The three limitations in the
readme that come from backspacing a live field fall out of the rule.

Words still arrive while you are speaking. They arrive in the listening
line immediately, and in the document as they settle. A token younger
than the stability window never appears in the app. That is locked by a
test that drives the engine and the mapper together. The host does not
grow a second timer.

People who liked watching the repair happen inside the document are not
imagining a feature we are deleting. That drawing comes back as the
underline, below. With the underline off, the document updates in
settled pieces and the line holds the rest. The landing page keeps
showing the repair in the field, because the page is a field we control.
The daemon matches the page when the underline is on.

### 2. You can see the unfinished sentence on every Linux desktop

Commit-only with nowhere to look is lag. The stability window is about
a second and a half, and a silent gap that long would feel like the
keyboard got worse.

The listening line is the molten text. It is not a caption of words
already in the app. The GNOME extension and the Windows pill already
draw a live caption. They become this line: the words move from the
line into the app as they freeze, and a scratch removes them from the
line.

GNOME is not the only Linux desktop. KDE, Sway, and Hyprland have no
extension. Version 3 includes a small window that does not take focus,
anchored at the caret when we know it and at a corner when we do not,
showing the same tail. Without that window, the release only works on
the desktop we already decorate.

Where the app can hold an underline, the line moves into the field. One
underline, in the app's own type, the mark people know from Chinese and
Japanese input. As a word settles, the underline lifts off it from the
left. That host is ibus, a separate process, off until you turn it on,
because registering an input method touches how the desktop types. It
is how the line gets into the field on GNOME. It is not the version.
Ghostty, kitty, Sway, and Hyprland keep the line and the forward
typing. A session that never attaches is a version 3 session, not a
fallback to 2.4.

The underline and the line obey one mapper. `PreeditMapper` already
turns frozen-plus-molten into commit, delete, and preedit. The ibus
process applies those operations. The listening line applies the same
pair by drawing the molten string and letting the sink type the frozen
delta. Neither path types `desired_text()`.

### 3. A command with no known destination stays a draft

Ordinary dictation still commits when the window cannot be named. Enter
stays suppressed and a spoken line break becomes a space, as in 2.4.
Refusing to type prose whenever focus is unknown would silence Wayland,
which is the desktop this version is for.

A command is different. Intent, and Kai's terminal route, stay on the
listening line until you say "keep it" when we cannot name the window.
We do not guess which prompt a command belongs to. When we can name a
terminal, the settled command types onto the prompt once, with no
Return. You press Enter yourself.

The filter keys off the newline choice, not off a register flag. The
python register pointed at a terminal can emit a newline from the
compiler. A raw commit of that string would press Return by another
name. `guard_commit` sits next to the injector's line-break strip and
runs on every commit while the newline choice is none. Return, keypad
Enter, Ctrl+M, and Ctrl+J are dropped on the forwarded-key path in that
same case.

If an input client is ever observed to submit on commit, that session
leaves the underline and types through the virtual keyboard with Enter
suppressed. The failure is draft keystrokes.

Once a client is attached, the field's purpose is the field. A terminal
purpose selects the terminal register and newline none. A password, a
PIN, or a hidden hint selects verbatim: no bias, no history, no
rewrite. A purpose wins over a late probe. The accessibility walk does
not start for that session. There is no purpose value for a code
buffer, and version 3 does not invent one. Code registers stay a choice
you make.

Unknown still means no Enter.

## What you feel

You tap Ctrl+Alt+V in the window you already focused.

The unfinished words show up on the line, or underlined in the field if
you turned that on. You hear one high tick when the microphone opens
and one low tick when it closes. Settled words appear in the app as
normal text, typed forward. The line shrinks from the left as they go.

While words are still unfinished, "scratch that" clears them. A click
or a key you press drops the unfinished tail and leaves what already
settled. After a phrase has landed, "scratch that" removes that phrase.
If the cursor has moved and the place is no longer sure, the phrase
stays and the line offers it so you can say "type it" where you are now.

A spoken "new line" in a chat is Shift+Enter after the words have
settled. Your own Enter still means what the page means. If unfinished
words are up when you press it, they settle first and then the Enter
goes through.

In a terminal, the command sits on the line until it settles, then
types onto the prompt with no Return. "New line" stays one line.
Nothing runs.

Kai stays off until you turn it on whenever a question would leave the
machine. Holding Right Ctrl does not type into the page. A command Kai
drafts uses the same line as a command you dictate, and it types only
when you say "keep it" if we cannot see the window. A tap cuts the
spoken answer off. The first time you summon Kai while it is off, you
hear one sentence about where a question would go. It does not repeat
all afternoon.

The rule, said once: unfinished isn't in the document. In the document
isn't run. Spoken only happens because you asked.

## First run

A new config asks one thing: where speech should be heard, a key or the
address of a speech server on this machine. Then it tells you to click
back into the window you care about and press Ctrl+Alt+V. You get
finished words in that window on this login. The listening line does
not wait for a logout.

The `input` group and a logout are asked only if the virtual keyboard
is not usable yet. The underline is a later yes, worded as showing
unfinished words in the app itself, and it leaves the keyboard you
already use in place.

`voice-keyboard setup` keeps the full walk for someone who asks. The
first time you say "make that formal," that is when it asks for a
language model. The first time you summon Kai and a question would
leave the machine, that is when it asks you to turn Kai on.

## How the underline is built

This is the drawing of rule 2, not a separate product.

The daemon keeps the microphone, speech-to-text, the flow engine, the
registers, and Kai. `voice_keyboard/imhost/` is the only thing that
speaks ibus. Its systemd user unit is installed disabled. ibus needs
the system `gi` bindings, so the host runs under `/usr/bin/python3`,
the same split the focus probe already uses. A host crash must not take
the microphone down.

The command socket accepts one command and closes. Preedit is a stream.
A second socket, mode 600, holds one long-lived connection.
Newline-delimited JSON. The host sends `hello`, `attach`, `detach`,
`ack`, and `reset`. The daemon sends `ops`, `keys`, and `clear`.

`[im] enabled` defaults to false. A missing key means off. An upgrade
does not write it, does not start the unit, and does not change input
sources. Doctor reports whether the host is registered and whether a
client is attached. With the flag off, version 3 is still version 3:
finished words, the listening line, commands held when the window is
unknown.

The mapper moves forward only after the host acks that generation. If
the ack never comes, the session keeps what the app already has. It
does not switch this utterance onto a second sink. Switching mid-phrase
is how text gets typed twice. The next recording may leave the
underline cleanly.

When the session ends, the underline clears and nothing extra commits.

## What does not move

Enter cannot be emitted by any path while the newline choice is none,
including a newline hidden in a paste.

A command is typed and left. The refusal stays in the sink.

Frozen text shrinks only because you scratched it, corrected it, or
undid it.

Kai under its default setting stays off when anything it does would
leave the machine.

A password field is never biased, never remembered, and never rewritten.

A personal word changes nothing until you accept it.

The microphone stays closed until you press, unless you have opted into
the wake word.

The underline is never turned on by an upgrade.

## Left out

These are real, and they are not this version. Shipping them instead of
the three things above would repeat 2.4: a larger minor.

Always-on dictation. The line can evaporate an unfinished tail, which
is the containment ambient mode needs, and it matters after the line is
what people see. The hotkey stays the hard mute.

A freedesktop submission. One ibus host will show whether commit and
preedit are enough. A provisional style and a code purpose stay local
until a second implementation exists.

Local fine-tuning, and another pass of spoken grammar. 2.4 was that
pass. The compiler in `voice_keyboard/flow/code.py` already turns "for
i in range ten colon" into code. Version 3 lets that compilation sit on
the line until the line freezes, then types it once. It does not grow a
new grammar to justify the number.

Flatpak. The job is to type into other apps, and to put a window on the
session. The curl installer and the AUR package stay the channels.

A Wayland input-method client for Sway and Hyprland. Those sessions get
the listening line and forward typing, which is the version. A second
process on the same socket comes after ibus has survived a release.

The public Grok realtime voice for Kai's spoken answers. Dictation stays
the transcribe stream, because that stream is what the engine freezes.
The Grok Voice plugin in Cursor is a skill for other apps. It is not
part of this keyboard. No waveform, no composer, no second app.

## Risks

The signature of 1.2 was words repairing themselves inside the field.
Moving that repair onto the line will feel like something was taken,
until the line is fast and obvious. If the line is late, small, or
missing on a desktop, the release fails even though the commit rule is
correct.

The line must not take focus and must not steal keys. A window that
becomes the focused app would make the next commit type into itself.

ibus remains a GNOME drawing. Sessions that do not run it have to feel
finished, not degraded. The `input` group stays required wherever the
virtual keyboard is how text lands.

The new unit is not tied to the daemon unit. Restarting the daemon
leaves a disabled host stopped.

Continuous integration does not need a compositor. The engine-to-mapper
test is pure. A fake host checks that the app's string equals the
frozen text, that the line equals the molten tail, and that a command
ending in a newline becomes the command with no Return when the newline
choice is none. The `gi` process is skipped unless an ibus address is
set. A recorded session on GNOME, and one on a desktop with no ibus,
is the acceptance test. Linux CI today does not prove that uinput
reaches a real app, and this version does not pretend a unit test
replaces that.

Before setup offers the underline, confirm on GNOME 45 through 50 that
the terminal widget reports a terminal purpose. If it does not, a
committed newline could submit. Until that is confirmed, a terminal we
cannot prove stays on forward typing with Enter suppressed.

## How the work is cut

Each slice is its own branch and its own pull request. None of them is
the release. The release is the three things above, in one version.

1. Commit-only typing, default on, with the molten tail on the overlay
   that already exists (GNOME and Windows). The engine accessors and
   the test ship here. This slice is already a behavior change. It is
   still not 3.0, because KDE and a bare Wayland session would go quiet.
2. The focus-less listening line for Linux desktops that have no shell
   extension. After this, every Linux session can see unfinished words.
3. Commands with no known destination stay on the line until "keep it."
   `guard_commit` lands with this, so a second sink cannot grow a
   Return.
4. The ibus host, unit installed disabled, `[im] enabled` defaulting to
   false. The line moves into the field when a client attaches. The
   keyboard is already version 3 without it.
5. The shorter first run, only when the config is new.

The Kai voice change does not share a branch with any of these.
